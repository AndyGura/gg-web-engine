# GG Web Engine Exporter (Blender add-on)

A Blender add-on that exports a scene to the format `@gg-web-engine/core`'s 3D GLB loader
(`Gg3dLoader.loadGgGlb`, and the `"Glb"` level-JSON class) reads: a binary glTF (`.glb`) plus a
JSON sidecar (`.meta`) carrying everything glTF has no slot for - empty objects ("dummies"),
curves/splines, and rigid body physics shapes.

This replaces the old `packages/core/blender_exporter/build_blender_scene.py` script, which shipped
as a loose file inside the `@gg-web-engine/core` npm package (so "installing" it meant knowing to
dig through `node_modules`) and had to be run as an external CLI wrapper around
`blender --background --python`. It's now a real installable Blender add-on with a `File > Export`
entry, and the export logic lives in exactly one place so other projects can install/update this
add-on instead of copy-pasting the script (which is how the old one drifted between projects).

## Installing

### Option A - download a release zip and install it (manual, works today)

1. Download `gg_web_engine_exporter-X.Y.Z.zip` from the
   [GitHub Releases page](https://github.com/AndyGura/gg-web-engine/releases) (tagged
   `blender-addon-vX.Y.Z` - the add-on is versioned and released independently of the npm packages,
   see `blender_manifest.toml`'s `version` field).
2. Blender 4.2+: **Edit > Preferences > Get Extensions > (▾ dropdown top-right) > Install from Disk**,
   pick the zip.
3. Blender < 4.2 (legacy add-on installer): **Edit > Preferences > Add-ons > Install...**, pick the
   zip, then enable the "GG Web Engine Exporter" checkbox. The same zip works for both install
   paths - `blender_manifest.toml` is used by 4.2+, the `bl_info` dict in `__init__.py` is used by
   older versions and is otherwise ignored.

### Option B - add the self-hosted repository (automatic updates, Blender 4.2+ only)

One-time setup, then future add-on updates show up in Blender's own Get Extensions UI like any
built-in extension:

1. **Edit > Preferences > Get Extensions > Repositories > + > Add Remote Repository**.
2. URL: `https://andygura.github.io/gg-web-engine/blender-extensions/index.json`
3. The "GG Web Engine Exporter" extension now appears under that repository - install/update/remove
   it from there going forward.

(This repository is a static `index.json` + zip generated by
`.github/workflows/blender_addon_release.yml` via Blender's own
`blender --command extension server-generate`, published to the `blender-extensions/` path on the
project's GitHub Pages site - not a submission to the official extensions.blender.org platform,
which is a reasonable later step once this add-on has some install base, but has its own review
process and stricter sandboxing constraints.)

## Using it

**File > Export > GG Web Engine (.glb + .meta)**. Options in the export panel:

| Option | Effect |
|---|---|
| Format | Only "GLB + .meta" exists today. See "Planned: exporting directly to Level JSON" below. |
| Export Materials | Uncheck to skip textures/materials entirely (faster export for a collision/layout-only pass). |
| Copyright | Written into the `.glb`'s glTF `asset.copyright` field. Empty by default - fill in your own if you want one. |

Picking a filename `foo.glb` writes `foo.glb` and `foo.meta` next to each other; point
`Gg3dLoader.loadGgGlb('.../foo')` (no extension) at that pair.

### Object conventions the exporter looks for

- **Meshes / lights** with `hide_render` off are included in the `.glb`. Modifiers are applied
  before export.
- **Empties** become "dummies" in `.meta` (position + rotation as a quaternion, plus any custom
  properties you've added on the object) - useful for spawn points, attachment points, or anything
  an app wants to look up by name after loading.
- **Curves** become splines in `.meta` (points in local-to-parent-chain space, `cyclic` flag, plus
  custom properties) - see `MapGraph3dEntity` for one consumer.
- **Objects with a Rigid Body** (Blender's own Physics > Rigid Body panel) become entries in
  `.meta`'s `rigidBodies` array: position (relative to the parent chain), rotation, collision shape,
  and - unless the object is itself a child of a `COMPOUND`-shaped rigid body, in which case it's
  nested under that parent's `shape.children` instead - body parameters (dynamic/mass/restitution/
  friction). Supported `Collision Shape` values: `BOX`, `SPHERE`, `CONE`, `CYLINDER`, `CAPSULE`,
  `CONVEX_HULL`, `MESH`, `COMPOUND`. Anything else raises an error at export time rather than
  silently producing a body the loader can't construct.

### Headless / CI batch export

`scripts/export_cli.py` imports the same `exporter.py` the operator uses (no drift between what an
artist gets from the menu and what a build pipeline produces), and doesn't require the add-on to be
installed - point `--python` at it from a checkout of this repo (or a copy of `blender-addon/`):

```bash
blender --background --python blender-addon/scripts/export_cli.py -- path/to/scene.blend [more.blend ...] [--skip-textures]
```

Each `.blend` is opened, exported to a `.glb`/`.meta` pair next to it, and the next one is loaded in
the same background process.

### Equirectangular → cubemap conversion (`tools/spherical_to_cube_texture.py`)

A standalone tool for converting an equirectangular skybox texture into six cubemap faces. It runs
on a regular system Python (needs `Pillow` and `numpy`), not inside Blender, so it isn't part of the
add-on zip - run it directly: `python tools/spherical_to_cube_texture.py texture.png`.

## Planned: exporting directly to Level JSON

Today this add-on only produces the GLB+meta sidecar format. A second, separate export mode is
planned - producing a GG level JSON document directly (see the `gg-engine-level-json` skill/docs)
instead of a `.glb`+`.meta` pair, so a scene authored once in Blender could load either as a single
GLB prop/model (today) or expand into first-class level entities (primitives, triggers, cameras,
custom app-registered classes) driven by the same object/empty/rigid-body conventions. `exporter.py`
already keeps scene-walking (`collect_scene_metadata`) separate from glTF-writing
(`export_glb_meta`) for this reason, and the operator's `export_format` is an `EnumProperty` with
one entry today so adding the second format later is a new enum item + `execute()` branch, not a
rework of the export panel. Not started - no target date.

## Testing

`e2e/blender-export/` builds a fixture scene headlessly, exports it with this add-on, and loads the
result back through a real `@gg-web-engine/three` + `@gg-web-engine/rapier3d` app, asserting the
three.js scene graph, the `.meta` sidecar, and the constructed physics bodies all match. Run it
after changing `exporter.py` or the `.meta` shape - see that directory's own README.

## Packaging / releasing (maintainers)

- `tools/package.sh` builds a validated zip into `dist/` via
  `blender --command extension build` (requires a `blender` binary on PATH - any 4.2+ works as the
  builder regardless of `blender_version_min` in the manifest).
- Bump `version` in `gg_web_engine_exporter/blender_manifest.toml` (and `bl_info["version"]` in
  `__init__.py` to match) and tag `blender-addon-vX.Y.Z` to trigger
  `.github/workflows/blender_addon_release.yml`, which builds the zip, publishes it as a GitHub
  Release asset, and regenerates the self-hosted repository index under
  `https://andygura.github.io/gg-web-engine/blender-extensions/` (via
  `blender --command extension server-generate`, merged into the existing GitHub Pages deployment
  with `keep_files: true` so it doesn't collide with the TypeDoc site `release_action.yml` deploys).
  This workflow has not yet been run for a real release - verify the first tag manually (check the
  Release assets and that the repository URL above resolves) before relying on it.
